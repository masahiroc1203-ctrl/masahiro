# NASバックアップ（nas-backup）

スマホの写真・動画を、家のWi-Fi経由でNASへバックアップするアプリです。
NAS（または家のPC）でサーバーを動かし、スマホのブラウザから開いてファイルを選ぶだけで保存できます。
**スマホにアプリをインストールする必要はなく、iPhone / Android どちらでも使えます。**

```
 ┌────────────┐   家のWi-Fi (LAN)    ┌──────────────────────────┐
 │  スマホ     │ ──────────────────▶ │ NAS (Docker) / 家のPC      │
 │  ブラウザ   │  http://NAS:8080    │  nas-backup サーバー       │
 │ ファイル選択 │ ◀────────────────── │   └ /volume1/photo/...     │
 └────────────┘                      └──────────────────────────┘
```

## 特徴

- **ファイルを選んでバックアップ**: 写真ライブラリから複数選択。何回かに分けて追加もできます
- **撮影日ごとに自動でフォルダ分け**: 写真の EXIF（JPEG / HEIC / DNG）や動画（MP4 / MOV）の撮影日時を読み取り、`2026/2026-11/` のように保存します。保存したファイルの更新日時も撮影日時に揃えます
- **大きな動画も途中から再開**: 8MBずつ分けて送るので、Wi-Fiが切れたりスリープしたりしても続きから送れます。ページを閉じてしまっても、同じファイルを選び直せば続きから再開します
- **重複はスキップ**: すでにバックアップ済みのファイルは選んだ時点で「済み」と表示し、送信しません
- **家族で使える**: 「保存先フォルダ名」に名前を入れると人ごとにフォルダを分けて保存します
- **上書きしない**: 同じ名前で中身が違うファイルは `IMG_0001 (1).JPG` のように別名で保存します
- **軽量**: 外部ライブラリ不要の Go 製。実行ファイル1つ（約6MB）または Docker で動きます

## 必要なもの

- NAS（Synology / QNAP / その他 Docker が動くもの）、または常時起動している家の PC・Raspberry Pi
- スマホと NAS が同じ家庭内ネットワークにあること

## インストール

### A. NAS の Docker で動かす（おすすめ）

Synology は「Container Manager」、QNAP は「Container Station」から使えます。

1. このフォルダ（`nas-backup/`）を NAS にコピーします（例: `/volume1/docker/nas-backup`）
2. NAS 上にバックアップ先のフォルダを作ります（例: 共有フォルダ `photo` の中に `SmartphoneBackup`）
3. `docker-compose.yml` の `volumes:` の左側を、2 で作ったフォルダのパスに書き換えます
   ```yaml
   volumes:
     - /volume1/photo/SmartphoneBackup:/backup
   ```
4. 起動します
   - **Synology**: Container Manager →「プロジェクト」→「作成」→ パスに 1 のフォルダを指定 → `docker-compose.yml` を使用 → 作成して起動
   - **SSH で操作する場合**: `cd /volume1/docker/nas-backup && sudo docker compose up -d --build`
5. スマホのブラウザで `http://<NASのIPアドレス>:8080` を開きます

> 保存されたファイルの所有者を NAS のユーザーにしたい場合は、`docker-compose.yml` の `user:` のコメントを外して uid:gid を指定してください（`id ユーザー名` で確認できます）。指定しないと root 所有になります。

### B. 家の PC / Raspberry Pi で動かす

実行ファイルを作って（`make dist` → `dist/` に各OS用ができます）、NAS の共有フォルダを保存先に指定して起動します。

```sh
# Linux / Raspberry Pi（NAS の共有フォルダを /mnt/nas にマウント済みの場合）
./nas-backup-linux-arm64 -dir /mnt/nas/photo/SmartphoneBackup

# Windows（NAS の共有フォルダを直接指定）
nas-backup-windows-amd64.exe -dir \\NAS\photo\SmartphoneBackup
```

起動すると、スマホで開くための URL が表示されます。

```
スマホのブラウザで開く: http://192.168.1.20:8080
```

> PC のファイアウォールでポート 8080 の受信を許可してください。

## スマホからの使い方

1. スマホを家の Wi-Fi につなぎ、`http://<NASのIPアドレス>:8080` を開く
2. （任意）「保存先フォルダ名」に名前を入れる（例: `papa`）
3. 「写真・動画を選ぶ」をタップして、バックアップしたいファイルを選ぶ
4. 「バックアップ開始」をタップ。送信中は画面を開いたままにしておく

**ホーム画面に追加**するとアプリのように起動できます。
- iPhone: Safari の共有ボタン →「ホーム画面に追加」
- Android: Chrome のメニュー →「ホーム画面に追加」

## 保存されるフォルダ構成

```
SmartphoneBackup/
├── papa/
│   ├── 2025/
│   │   └── 2025-12/
│   │       ├── IMG_0001.HEIC
│   │       └── IMG_0002.MOV
│   └── 2026/
│       └── 2026-11/
│           └── IMG_0103.JPG
├── mama/
│   └── ...
└── .nasbackup/          ← アプリの管理用（バックアップ済み一覧・送信途中のファイル）
```

- 撮影日時が読み取れないファイルは、スマホ側のファイル更新日時で振り分けます
- `BACKUP_LAYOUT=flat` にすると年月フォルダを作らず、保存先フォルダ直下に保存します
- 送信途中で止まったまま 7 日経ったファイルは自動で削除されます

## 設定

環境変数（Docker）またはコマンドライン引数で設定します。

| 環境変数 | 引数 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `BACKUP_DIR` | `-dir` | `./backup`（Docker では `/backup`） | 保存先フォルダ |
| `LISTEN_ADDR` | `-addr` | `:8080` | 待ち受けポート |
| `BACKUP_LAYOUT` | `-layout` | `date` | `date`: 撮影年月ごと / `flat`: 分けない |
| `BACKUP_PASSWORD` | `-password` | なし | 設定するとアクセス時にパスワードを聞かれる（ユーザー名は何でも可） |
| `TZ` | – | `Asia/Tokyo`（Docker） | 年月フォルダを決めるタイムゾーン |

## 注意点

### セキュリティ
- **家庭内ネットワーク専用です。ルーターでポート開放してインターネットに公開しないでください**（通信は暗号化されていない HTTP です）
- 家族以外も使う Wi-Fi（ゲスト Wi-Fi など）がある場合は `BACKUP_PASSWORD` を設定してください
- ファイル名に含まれる `../` などは取り除かれ、保存先フォルダの外に書き込まれることはありません

### スマホ側の制限
- **送信中は画面を開いたままにしてください。** ブラウザの仕様上、画面を消したり他のアプリに切り替えたりすると送信が止まります。戻ってくると自動で再開し、止まったままの場合は「バックアップ開始」で続きから送れます
- 写真ライブラリから選ぶと、端末や設定によっては写真の形式が変換されたり（HEIC → JPEG など）、動画が圧縮されたり、位置情報が省かれたりすることがあります。オリジナルのまま残したい場合は、保存されたファイルの形式・サイズを一度確認し、必要に応じて「ファイルアプリ・フォルダから選ぶ」を使ってください
- 端末によっては、写真ライブラリから選んだファイルの名前が数字だけになることがあります（中身や撮影日での振り分けには影響しません）

### 重複の判定について
「保存先フォルダ名・ファイル名・ファイルサイズ」が同じファイルをバックアップ済みとみなします。
NAS 上のファイルを削除した場合は、もう一度バックアップできます。

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| スマホでページが開けない | スマホが家の Wi-Fi につながっているか（モバイル通信になっていないか）、NAS の IP アドレス・ポートが正しいか、NAS / PC のファイアウォールで 8080 番が許可されているかを確認 |
| 「NASの空き容量が足りません」 | NAS の容量を空けてから「失敗したファイルを再試行」 |
| 撮影日と違うフォルダに入る | 撮影日時の情報が無いファイルは更新日時で振り分けます。`TZ` の設定も確認してください |
| 保存したファイルを NAS のユーザーで消せない | Docker の `user:` に NAS ユーザーの uid:gid を設定 |

## 開発

```sh
make run     # ./backup に保存する開発サーバーを起動 (http://localhost:8080)
make test    # テスト
make dist    # 各OS用の実行ファイルを dist/ に作成
make docker  # Docker イメージを作成
```

### ファイル構成

| ファイル | 内容 |
| --- | --- |
| `main.go` | 起動・設定の読み込み |
| `server.go` | HTTP API |
| `store.go` | 保存処理（再開・重複判定・フォルダ分け） |
| `metadata.go` | 撮影日時の読み取り（JPEG / HEIC / MP4 / MOV / TIFF） |
| `web/` | スマホ用の画面（HTML / CSS / JavaScript、実行ファイルに埋め込み） |

### API

| メソッド | パス | 説明 |
| --- | --- | --- |
| `GET` | `/api/status` | 空き容量・設定 |
| `POST` | `/api/check` | `{owner, files:[{name,size}]}` → バックアップ済みかどうか |
| `POST` | `/api/uploads` | `{name, size, lastModified, owner}` → `{status, id, offset}`。`status` が `exists` ならバックアップ済み。送信途中なら続きの `offset` を返す |
| `PUT` | `/api/uploads/{id}` | ヘッダ `Upload-Offset` の位置からデータを追記。最後まで届くと `{status:"done", path}`。位置がずれていると `409` と正しい `offset` を返す |

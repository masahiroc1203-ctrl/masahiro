# 住環境エネルギー分析（温度 × 電力 × ガス）

家の温度データ・電力使用量・ガス使用量の関係を分析し、効率的な住環境を維持するための改善点を洗い出すツール。

## 何がわかるか

1. **ベース電力**: 空調に依らない常時消費（待機電力など）が全体の何割か
2. **暖房/冷房の温度感応度**: 外気温が1°C変わると電力が何kWh増えるか → 断熱投資の優先度判断
3. **ガスの分解**: 給湯・調理のベース分と暖房起因分を月次HDD回帰で分離 → ガス暖房をエアコンに移すべきかの判断材料
4. **快適性**: 室温が快適域（18–28°C）にある割合、冬の底冷え日数

## 使い方

```bash
cd home_energy
pip install -r requirements.txt

# 1) まずサンプルデータで動作確認
python generate_sample_data.py
python analyze.py

# 2) 実データが用意できたら data/ のCSVを置き換えて再実行
python analyze.py
```

結果は `output/report.md` と `output/*.png` に出力される。

## 実データの入れ方（data/ のCSV形式）

### `data/temperature.csv` — 日次（自作ロガー / SwitchBot等のエクスポート）

```csv
date,indoor_temp_c,outdoor_temp_c
2026-01-01,19.5,4.2
```

- 時間単位のログを持っている場合は日平均に集計してから入れる
- 外気温は気象庁の[過去の気象データ](https://www.data.jma.go.jp/gmd/risk/obsdl/)から最寄り観測所の日平均気温をダウンロードしてもよい

### `data/electricity_hourly.csv` — 部屋別・時間別（HEMS回路別計測。**推奨**）

HEMS端末（AiSEG2等）の回路別データをロング形式で入れる。これがあると部屋別分析が有効になり、`electricity.csv` は不要（時間別から日次を自動集計する）:

```csv
datetime,room,kwh
2026-01-01 00:00,LDK,0.12
2026-01-01 00:00,Bedroom,0.05
```

- `room` はHEMSの回路名そのままでよい（※グラフは日本語フォントがない環境だと文字化けするため、英数字名を推奨）
- HEMSのエクスポート形式（横持ちCSV等）はそのままでは入らないので、実物を見て変換スクリプトを足す想定

### `data/electricity.csv` — 日次（時間別データがない場合のフォールバック）

カテエネ（中部電力ミライズ）のマイページ →「電気の使用量」→ CSVダウンロードで日別データが取れる。列名を合わせて保存する:

```csv
date,electricity_kwh
2026-01-01,14.2
```

### `data/gas.csv` — 月次（Club TOHOGAS / 検針票）

東邦ガスのClub TOHOGASマイページか毎月の検針票から転記する:

```csv
month,gas_m3
2026-01,52.3
```

## 設定の調整（config.py）

| 定数 | 意味 | 既定値 |
| --- | --- | --- |
| `HDD_BASE_C` | 暖房が必要になる外気温の基準 | 18°C |
| `CDD_BASE_C` | 冷房が必要になる外気温の基準 | 24°C |
| `ELECTRICITY_YEN_PER_KWH` | 電力単価（金額換算用） | 31円 |
| `GAS_YEN_PER_M3` | ガス単価（金額換算用） | 210円 |

契約プランの実単価に合わせて更新すると金額推定の精度が上がる。

## 前提としている住まいのモデル

- 暖房: **ガス温水床暖房がメイン**（→ ガスのHDD回帰の傾き＝床暖房の温度感応度）、たまにエアコン（→ 電力の暖房感応度は補助暖房分）
- 冷房: **各部屋エアコン**（→ 部屋別冷房感応度で効率を比較）
- 1F: リビングダイニング（**吹き抜け** → 冷房効率・温度成層に注意）
- 2F: 浴室・寝室・書斎・室内干しカウンター

## データの自動取得（家の端末 → このリポジトリ）

このリポジトリのセッションから家のLANには入れないため、「家側で吸い出して外に置く」部分だけ家側の仕組みが要る。選択肢:

| 方式 | 手間 | 自動化度 |
| --- | --- | --- |
| A. Raspberry Pi等でHEMSをLANポーリング → 日次で `git push` | 初期構築のみ | 完全自動 |
| B. HEMS端末からUSB/SDエクスポート → Google Driveへ | 月1回程度の手作業 | 半自動 |
| C. CSVを手動でこのリポジトリ/会話にアップ | 都度 | 手動 |

A の構成例（AiSEG2の場合）: 同一LANのRaspberry PiからローカルWeb API（digest認証、本体記載のID/パスワード）で回路別電力を取得するか、Home AssistantのAiSEG2連携で蓄積 → cronで `electricity_hourly.csv` に追記して push。

## 分析手法メモ

- **度日（degree-day）回帰**: 月次ガス使用量を `gas = a × HDD + b` に回帰。`b` が給湯・調理のベース、`a × HDD` が暖房分。住宅エネルギー分析の標準手法
- **3域分割**: 電力は外気温で「暖房域（<18°C）/ 中間域 / 冷房域（>24°C）」に分け、中間域の平均をベース電力とみなす
- 回帰はサンプル数が `MIN_REGRESSION_SAMPLES` 未満なら算出しない（少データでの誤解を防ぐ）

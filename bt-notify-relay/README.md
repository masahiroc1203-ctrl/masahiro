# BT-Notify-Relay

PC の予定やリマインダーを Bluetooth で Android スマホに送り、スマホの通知として出します。
その通知をバンドの公式アプリ（Mi Fitness など）がバンドに転送するので、バンド独自の通信方式を解析せずに PC からバンドへ通知を届けられます。

```
PC (pc-sender)  ──Bluetooth RFCOMM / 1行1JSON──▶  スマホ (android-relay)  ──公式アプリの通知転送──▶  バンド
 Outlook・ICS の予定                               Android の通知として表示
 自作リマインダー・クイックタイマー
```

| フォルダ | 中身 |
| --- | --- |
| `pc-sender/` | Windows のタスクトレイ常駐アプリ（C# / .NET 8 / WinForms） |
| `pc-sender.Tests/` | PC 側の単体テスト（通信形式・リマインダー時刻・ICS・設定） |
| `android-relay/` | Android アプリ（Kotlin、Android 10 以上） |
| `docs/spec.md` | 仕様書（Gemini で作成） |

## 試し方

### 0. 準備
- PC とスマホを Bluetooth でペアリングしておく（chihara-PC と S25 は済み）
- PC に .NET 8 SDK を入れる: `winget install Microsoft.DotNet.SDK.8`
  - `dotnet --list-sdks` に `8.0.xxx` が出れば OK

### 1. スマホ側（先にこちら）
1. Android Studio で `android-relay` フォルダを開き、スマホをつないで ▶（Run）
   - コマンドなら `android-relay` で `gradlew.bat installDebug`（スマホの「USB デバッグ」をオンにしておく）
2. アプリで「サービス開始」を押し、「付近のデバイス」と「通知」を許可する
3. 「バッテリー最適化の除外設定を開く」で除外する（しないと、しばらくして止まることがある）
4. 「テスト通知を発行」を押し、スマホに通知が出るのを確かめる
5. バンドの公式アプリのアプリ通知設定で「BT Notify Relay」をオンにし、もう一度テスト通知 → **バンドに届けばスマホ側は完成**

### 2. PC 側
```powershell
cd bt-notify-relay\pc-sender
dotnet run
```
- タスクトレイに「BT」の丸いアイコンが出ます。**緑 = 接続中 / 黄 = 検索・待機中 / 赤 = エラー**。状態は右クリックメニューの一番上にも出ます
- 右クリック →「テスト通知を送信」→ スマホ → バンドに届けば成功
- 「クイックタイマー」→「5分後に通知」で、5 分後に届くか
- 予定: クラシック版 Outlook を起動しておき、「予定を今すぐ再読み込み」で件数が出るか。予定の 10 分前・5 分前・開始時刻に届きます

### 設定（config.json）
トレイメニューの「config.json を開く」で開き、保存したら「設定を反映して再起動」を押します。
`dotnet run` で起動したときの実体は `pc-sender\bin\Debug\net8.0-windows10.0.19041.0\config.json` です（ビルドすると `pc-sender\config.json` で上書きされます）。

| 項目 | 意味 | 既定値 |
| --- | --- | --- |
| `target_device_name` | ペアリング済みスマホの名前に含まれる文字（部分一致） | `"S25"` |
| `enable_outlook_com` | 起動中のクラシック版 Outlook から予定を読む | `true` |
| `ics_sources` | ICS ファイルのパスや URL（Google カレンダー・新しい Outlook の「ICS 形式の限定公開 URL」など） | `[]` |
| `reminder_minutes_before` | 予定の何分前に通知するか | `[10, 5, 0]` |
| `custom_reminders` | 毎日・曜日指定のリマインダー（`time` は `"10:30"`、`days` は `"Mon"` や `"月"`。空なら毎日） | 平日 10:30 と 17:15 |
| `quiet_hours_start` / `quiet_hours_end` | この時間帯は予定・リマインダーを送らない | `"23:00"`〜`"07:00"` |

テスト通知とクイックタイマーは、静かな時間帯でも送ります。

## うまくいかないとき

| 表示・症状 | 対処 |
| --- | --- |
| 赤「ペアリング済みに「S25」なし (…)」 | カッコ内がペアリング済みの機器名。`target_device_name` をスマホの名前の一部にする |
| 黄「スマホのアプリで「サービス開始」を押してください」 | スマホのアプリでサービスを開始する。状態が「PCからの接続を待機中」になっていれば、5〜30 秒以内につながる |
| 黄「スマホに届きません (…)」 | スマホの Bluetooth がオフ、または離れすぎ |
| 「未接続のため保留しました」 | つながると自動で送ります（最大 50 件・15 分まで） |
| スマホには出るがバンドに来ない | 公式アプリの通知設定で「BT Notify Relay」がオンか。スマホの通知設定で「PC転送通知」チャンネルがオンか |
| しばらくすると止まる | スマホでバッテリー最適化の除外。PC のスリープ復帰時は自動でつなぎ直します（メニューの「今すぐ再接続」でも可） |
| Outlook の予定が 0 件 | 「新しい Outlook」は COM で読めません。クラシック版を起動しておくか、`ics_sources` に ICS の URL を入れる |

## Gemini 版からの変更点

Gemini のチャットにあったコードは、最初のコミットにそのまま入れてあります。動かすために直したところ:

- **ビルドが通らない**: `Marshal.GetActiveObject` は .NET 8 に無いので、Win32 API（`GetActiveObject`）で置き換えた
- **Android のプロジェクトが無い**: Gradle の設定・ラッパー・アイコンを追加し、APK をビルドできるようにした
- **数時間で止まる**: PC が Android からの `pong` を読んでいなかったため、受信バッファが詰まるとスマホ側の処理が止まる作りだった。PC で読むようにし、75 秒応答が無ければつなぎ直す
- **リマインダーの取りこぼし**: 「指定時刻の前後 45 秒」に 30 秒おきのチェックが入る前提だったため、予定の読み込みが遅いと鳴らなかった。前回チェックから今回までに来た時刻を送る方式にした
- **未接続中の通知が消える**: 保留して、つながったら送る
- **PC のスリープ復帰で切れたまま**: 復帰を検知してすぐつなぎ直す。スマホ側も、古い接続が残っていても新しい接続を受け付ける
- **スマホに消せない「停止中」通知が残る**: サービス停止時の通知の出し直しをやめた
- **権限を拒否するとアプリが落ちる**: Android 14 以降は「付近のデバイス」が無いと常駐できないので、確認してから開始する
- **接続先の既定値**: `"Galaxy"` では S25 の名前に一致しないので `"S25"` にした
- **ICS**: 繰り返し予定（毎日・毎週）、EXDATE、個別に変更された回、TZID に対応。UID が無いときの ID が `{startLocal:ticks}` で壊れていたのを直した
- **Outlook**: 繰り返し予定の展開で件数が当てにならない問題を避けるため `GetFirst` / `GetNext` でたどる。読んだあと COM の参照を解放する
- **トレイ**: 状態でアイコンの色が変わる、メニューに状態を表示、テスト送信の結果を表示、二重起動の防止、設定の再読み込み
- spec.md は `docs/` に置いた（中身は変えず、末尾に実装メモを追加）

## まだできないこと
- **Windows のトースト通知（Teams・Slack など）の転送**: `UserNotificationListener` はパッケージ化（MSIX）したアプリでしか使えないため、`NotificationWatcher.cs` は置いてあるだけで使っていない
- 好きな分数とメモを入れられるタイマー、スタートアップへの自動登録、接続先をメニューで選ぶ機能（Gemini の次の案）
- スマホ再起動時の自動開始（`RECEIVE_BOOT_COMPLETED`）
- ICS の毎月・毎年の繰り返し（初回だけ扱う）、終日予定（リマインドしない）

## 開発メモ
- PC 側の単体テスト: `cd pc-sender.Tests && dotnet test`（Windows 以外でも動く）
- Android の単体テスト: `cd android-relay && gradlew testDebugUnitTest`
- PC 側は `EnableWindowsTargeting` を入れてあるので、Linux でもビルドだけはできる（実行は Windows のみ）
